# V-MAX — план городского досуга в MAX

V-MAX помогает собрать прогулку, посещение мест и выбранные события на один или несколько дней. Пользователь задаёт город, время, старт, интересы и при необходимости бюджет. Бот и мини-приложение работают с одним сохранённым планом: условия можно изменить, а найденные места — открыть на карте.

Рабочий режим `external` подбирает места с приблизительным запасом на переходы и передаёт старт, выбранные остановки по порядку и финиш в 2ГИС одной ссылкой. Реальный путь, время в дороге и доступность строит 2ГИС. Встроенная карта показывает найденные точки без линии маршрута. Режим `verified` с внутренней проверкой дорог сохранён для отдельной конфигурации с Routing API; по умолчанию он не включён.

## Запуск в Docker

Нужен Docker с Compose. Скопируйте `.env.example` в `.env.local` и заполните значения для MAX, PostgreSQL, 2ГИС Places и MapGL. `POSTGRES_PASSWORD` — отдельный пароль локальной базы из букв и цифр. Ключи Yandex требуются для разбора свободного текста; без них остаётся ручное создание условий. Не помещайте рабочие ключи в репозиторий.

```sh
docker compose --env-file .env.local up --build -d
```

Compose поднимет приложение и PostgreSQL; локальный адрес — `http://127.0.0.1:3000`. Для проверки сервера откройте `/api/health`: ответ должен быть 200. `/api/planning/bootstrap` без подписанных данных MAX должен вернуть 401. Основной сценарий нужно открывать через привязанное мини-приложение в MAX: прямой вход с localhost без MAX-авторизации намеренно закрыт.

Остановка и повторный запуск:

```sh
docker compose --env-file .env.local down
docker compose --env-file .env.local up --build -d
```

Данные PostgreSQL сохраняются в Docker-томе. Не используйте `down -v`, если хотите сохранить планы.

## Как проверить сценарий

1. Откройте [бота V-MAX в MAX](https://max.ru/t801_hakaton_max_bot) и выберите «Новый маршрут».
2. Напишите пожелание, например «Хочу погулять, а потом поесть», укажите город, дату, временное окно и старт.
3. Подтвердите условия. Бот покажет найденные места; откройте мини-приложение для карты и полного списка.
4. Нажмите «Посмотреть на карте», чтобы передать все точки выбранного дня в 2ГИС. Отдельные ссылки карточек ведут к конкретному месту.
5. Измените условие или откройте «Мои маршруты», чтобы вернуться к подборке. Через 30 минут появится напоминание обновить данные, но сохранённая подборка останется доступной.

При неполном поиске или несовместимых условиях приложение показывает причину и предлагает изменить параметры; оно не подставляет учебные места вместо ответа провайдера. Для выбранных событий KudaGo отдельно проверяются доступные сеансы, площадка и возрастные ограничения. Билеты и бронирование не оформляются.

В «Добавить событие» доступны категории афиши: выставки, спектакли, концерты, специальные кинопоказы, экскурсии, фестивали и другие события. Поддерживаются города текущего каталога KudaGo: Москва, Санкт-Петербург, Нижний Новгород, Казань и Екатеринбург; наличие событий на нужный день зависит от источника. Обычные кафе, прогулочные места и природа подбираются через 2ГИС. Афиша KudaGo не заменяет полное расписание кинотеатров.

Выбранный сеанс сохраняет официальные начало и конец; для выставки пользователь выбирает длительность в пределах часов площадки. План учитывает приблизительную дорогу и ставит выбранное событие выше дополнительных остановок, сохраняя заданный порядок занятий. Точная или ограниченная цена входа учитывается по верхней границе на каждого участника; цена «от» остаётся неизвестной. В результате видны время события, оценка билетов для группы и ссылка на источник. Наличие билетов нужно проверить у организатора.

## Настройки

| Параметр | Назначение |
|---|---|
| `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME` | Бот, проверка запуска мини-приложения и webhook. |
| `POSTGRES_PASSWORD` | Пароль локальной базы в Compose. `DATABASE_URL` для приложения Compose формирует сам. |
| `PUBLIC_BASE_URL` | Публичный HTTPS-адрес при размещении в MAX. |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Необязательный разбор свободного текста через Alice Flash. |
| `DGIS_PLACES_API_KEY` | Серверный поиск мест. |
| `DGIS_BACKUP_API_KEY`, `DGIS_TERTIARY_API_KEY` | Необязательные резервные ключи доступных сервисов 2ГИС. |
| `DGIS_MAPGL_API_KEY` | Браузерный ключ встроенной карты. Для production лучше отдельный ключ с разрешёнными origin. |
| `DGIS_MAPGL_ALLOW_SHARED_DEMO_KEY` | Явное исключение для общего демо-ключа, разрешённое владельцем на этапе хакатона. Такой ключ будет виден посетителям. |
| `PLANNING_ROUTING_MODE` | `external` по умолчанию; `verified` требует Routing API и учёта квоты. |
| `DGIS_ROUTING_API_KEY` | Серверный ключ только для `verified`. |
| `DATABASE_CA_PATH` или `DATABASE_CA_PEM` | Проверяемое TLS-соединение с облачной PostgreSQL; выбирается один способ. |
| `MAX_WEBHOOK_ASYNC` | Настройка фоновой обработки на поддерживаемой облачной платформе; локальный Compose работает синхронно. |

Полный перечень и безопасные значения по умолчанию находятся в [.env.example](.env.example). В production секреты передаются через Lockbox, а не через Git. Публичный ключ MapGL отдаётся браузеру только при разрешённой конфигурации.

## Устройство проекта

- `src/client/` — интерфейс React и MAX UI, карта MapGL и MAX Bridge.
- `src/server/` — Fastify API, MAX webhook, нормализация внешних данных, хранение планов и проверка авторизации.
- `src/shared/` — общие типы и пользовательские тексты.
- `planner/` — детерминированный подбор мест и событий на Python/OR-Tools.
- `openapi.yaml`, `DATA-API.yaml`, `test-data/api-scenarios.json` — контракт API и синтетические сценарии.
- `Dockerfile`, `compose.yaml`, `.dockerignore` — воспроизводимая контейнерная поставка.

LLM разбирает формулировку пожелания, но не выбирает итоговые места и не подтверждает время, цены или маршрут. Внешние карточки сохраняют источник и время получения; тестовые данные обозначены в интерфейсе. Сервер проверяет подпись `initData` и принадлежность плана пользователю. Подробности сторонних зависимостей и лицензий — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Проверки и разработка

Информация о сервисе доступна без входа по `/?page=information`, внизу мини-приложения и через `/privacy` в боте. В `docs/` находятся отдельные шаблоны политики, условий использования и согласия. Реквизиты оператора пока не заполнены; шаблоны не являются действующими юридическими документами. До утверждения политики нужно проверить основания обработки, уведомление Роскомнадзора, регионы и сроки хранения у провайдеров, журналов и резервных копий.

```sh
npm ci
npm run check
npm run check:secrets
npm run planner:test
```

`npm run check` выполняет типизацию, тесты и сборку. Тесты PostgreSQL требуют отдельной временной базы через `TEST_DATABASE_URL`; без неё они пропускаются. Python-зависимости закреплены в `planner/uv.lock`. Учебный прогон без внешних API: `npm run planner:demo`. Проверка OpenAPI после изменения контрактов: `node --import tsx scripts/api-contract.mts`.

Для разработки вне Docker: `npm run dev` после установки зависимостей и настройки PostgreSQL. Vite слушает порт 5173, API — 3000. Локальный экран без подписанных MAX-данных не открывает чужие планы. CI повторяет проверки на Linux и собирает Docker-образ.

## Развёртывание и ограничения

Рабочий адрес мини-приложения: `https://bbapc7qgk242slpm2df5.containers.yandexcloud.net/`. Скрипт `node scripts/deploy-yandex-live.mjs --apply --external-places-demo` обновляет существующий контейнер после проверки конфигурации, версии Lockbox и доступности базы; он не создаёт нового бота. Перед использованием скрипта нужны действующие `yc`, Docker и права на имеющиеся ресурсы. После деплоя проверьте сценарий внутри MAX.

Подбор ограничен выбранным радиусом и полученными ответами 2ГИС. В режиме `external` время посещения и переходов — оценки, а не измеренный путь; фактические часы работы, цены и дорогу проверьте перед поездкой. Промежуточные точки в ссылке подтверждены в веб-версии 2ГИС и [описаны для Android](https://help.2gis.ru/question/razrabotchikam-zapusk-ideystviya-vmobilnom-prilozhenii-cherez-deeplink); iOS ещё не проверен. Долгие ответы webhook в serverless остаются отдельным риском до подтверждения фоновой обработки. Рабочий MAX и Docker-проверка — разные части приёмки: успешный `/api/health` не подтверждает живой маршрут пользователя.

Радиус по умолчанию: пешком 5 км, велосипед 10 км, общественный транспорт и такси 30 км, автомобиль 50 км. Явно заданный пользователем радиус сохраняется. Неуточнённое «поехать» предлагается как выбор между общественным транспортом и автомобилем; сервер не назначает один из них сам.

Разрешение на сохранение результатов 2ГИС до удаления пользователем подтверждено владельцем проекта.
