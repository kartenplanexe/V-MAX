# V-MAX

Планировщик досуга в MAX: помогает выбрать места и события на свободное время, собрать их в план дня и открыть маршрут в 2ГИС.

[Открыть бота](https://max.ru/t801_hakaton_max_bot) · [Мини-приложение](https://bbapc7qgk242slpm2df5.containers.yandexcloud.net/) · [Репозиторий](https://github.com/kartenplanexe/V-MAX)

## Как это работает

1. Пользователь пишет боту, например: «Завтра с 14 до 18 хочу погулять пешком в Нижнем Новгороде, а потом поесть». Можно обойтись без свободного текста и заполнить форму.
2. Бот уточняет недостающие условия. Пользователь выбирает старт, проверяет время, бюджет и способ передвижения.
3. Сервис ищет места в 2ГИС. Через «Добавить событие» можно выбрать событие KudaGo и его сеанс либо время посещения.
4. Планировщик учитывает порядок занятий, доступное время, бюджет, выбранные события и примерное время между остановками.
5. Мини-приложение показывает план и карту. План можно сохранить, изменить или поделиться его условиями. Кнопка «Посмотреть на карте» передаёт в 2ГИС все остановки по порядку.

В стандартном режиме `external` дорогу строит 2ГИС после перехода по ссылке. V-MAX оценивает переходы для подбора мест, но не обращается к Routing API. Билеты и бронирование остаются на стороне организатора или заведения.

## Устройство проекта

```text
MAX: бот и мини-приложение
          ↓
Fastify API ──→ Alice Flash: условия из свободного текста
     │       ├→ 2ГИС: места, адреса и категории
     │       └→ KudaGo: события, сеансы и площадки
     ├──→ Python: подбор и проверка ограничений
     └──→ PostgreSQL: диалоги, условия и сохранённые планы
```

LLM разбирает запрос, но не придумывает места, цены и расписания. Сервер проверяет ответ модели; пользователь подтверждает условия перед расчётом. Браузер получает карту через 2ГИС MapGL, а к остальным источникам обращается сервер.

| Каталог или файл | Для чего нужен |
|---|---|
| `src/client/` | React-интерфейс, формы, план дня, карта, MAX UI и Bridge. Входная точка — `main.tsx`. |
| `src/server/index.ts` | HTTP-сервер, подключение БД и регистрация API. |
| `src/server/max-chat.ts` | Диалог бота и обработка его кнопок. |
| `src/server/intent/`, `intent-start.ts` | Промпты, проверка и преобразование ответа LLM. |
| `src/server/dgis.ts`, `kudago.ts` | Клиенты внешних каталогов. |
| `src/server/place-planning.ts`, `event-planning-routes.ts` | Поиск кандидатов, выбор событий и запуск планировщика. |
| `src/server/durable-planning.ts`, `planning-database.ts`, `planning-schema.sql` | Общее состояние, сохранение в PostgreSQL и миграции. |
| `src/shared/` | Типы, схемы запросов и общие правила для клиента и сервера. |
| `planner/` | Python-планировщик; `run.py` принимает JSON, `src/vmax_planner/` выполняет расчёт. |
| `scripts/` | Сборка, проверки, настройка webhook и развёртывание. |
| `test-data/`, `planner/tests/`, `*.test.ts` | Тестовые сценарии и автоматические тесты. |
| `Dockerfile`, `compose.yaml`, `.env.example` | Сборка, запуск приложения с БД и образец настроек. |
| `openapi.yaml`, `DATA-API.yaml` | Контракт HTTP API и последовательность проверок для жюри. |

Стек: Node.js 24.15.0, TypeScript, React, Fastify, Python 3.12.13, OR-Tools, PostgreSQL 17. OR-Tools используется в дополнительном режиме `verified`; стандартный `external` выполняет подбор в Python без CP-SAT. Версии библиотек закреплены в `package-lock.json` и `planner/uv.lock`; версии образов — в Dockerfile и Compose. Сведения о лицензиях — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Установка и запуск

**Для установки нужны только Git, Docker с Compose и ключи сервисов. Node.js, Python и uv на компьютере устанавливать не требуется.** Выполните шаги 1–4. Шаг 5 нужен для проверки своей установки внутри MAX.

### 1. Получите исходный код

```sh
git clone https://github.com/kartenplanexe/V-MAX.git
cd V-MAX
```

Для проверки конкурсной версии переключитесь на commit, указанный на первом слайде презентации: `git checkout <commit>`. Если получили ZIP, распакуйте его и откройте терминал в каталоге с `compose.yaml`.

### 2. Заполните настройки

Скопируйте `.env.example` в `.env.local` любым файловым менеджером. В `.env.local` заполните:

| Переменная | Что указать |
|---|---|
| `POSTGRES_PASSWORD` | Новый пароль локальной БД из букв и цифр, не менее 20 символов. |
| `MAX_BOT_TOKEN` | Токен бота MAX. |
| `MAX_BOT_USERNAME` | Username этого бота. В шаблоне указан выданный команде бот. |
| `DGIS_PLACES_API_KEY` | Ключ 2ГИС с доступом к Places, Categories и Regions. |
| `DGIS_MAPGL_API_KEY` | Ключ MapGL для карты с доступом к Map Tiles; разрешите адрес вашей установки. |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Доступ к Alice Flash в Yandex AI Studio. Нужен для свободного текста; ручная форма работает без этих двух значений. |

Оставьте `PLANNING_ROUTING_MODE=external`. **Остальные поля для локального Compose менять не нужно.** `PUBLIC_BASE_URL` заполните на шаге 5. Если у вас один демо-ключ 2ГИС для поиска и карты, укажите его в обоих полях и задайте `DGIS_MAPGL_ALLOW_SHARED_DEMO_KEY=true`: ключ карты будет виден в браузере.

KudaGo работает без ключа. MAX, 2ГИС, KudaGo и Yandex AI Studio — внешние сервисы: для полного сценария нужны сеть, действующие доступы и доступная квота. Рабочие ключи для жюри передаются отдельно от публичного репозитория. Резервные ключи, облачная БД и другие необязательные параметры описаны в [настройках](docs/configuration.md).

### 3. Запустите приложение и базу

```sh
docker compose --env-file .env.local up --build -d
```

Команда собирает приложение, устанавливает Node- и Python-зависимости, запускает PostgreSQL и применяет миграции. Для первой сборки требуется доступ к реестрам Docker, npm и PyPI.

| Компонент | Адрес или порт |
|---|---|
| Приложение и API | `http://127.0.0.1:3000`; внутри контейнера — `8080`. |
| PostgreSQL | `database:5432`, доступна только контейнерам Compose. |

### 4. Проверьте запуск

```sh
docker compose --env-file .env.local ps
curl http://127.0.0.1:3000/api/health
```

Ожидаются работающие контейнеры и HTTP 200 с `{"service":"v-max","status":"ok","version":"0.1.0"}`. В Windows PowerShell используйте `curl.exe`, если `curl` является псевдонимом.

Открытие мини-приложения в обычной вкладке не даёт авторизацию MAX: запрос к `/api/planning/bootstrap` без подписанных данных возвращает 401. Для формы с вымышленными данными без MAX есть отдельный [локальный пример](docs/development.md#пример-без-ключей).

Если запуск не удался, посмотрите `docker compose --env-file .env.local logs --tail=100 app database`. Ошибка пароля после его смены обычно означает, что том БД создан со старым паролем: верните прежнее значение или смените пароль роли в БД. Пересоздание контейнеров само по себе пароль не меняет.

### 5. Подключите свою установку к MAX

Этот шаг **не нужен**, если проверяете уже работающего [бота команды](https://max.ru/t801_hakaton_max_bot).

1. Предоставьте публичный HTTPS-адрес с доверенным сертификатом, направленный на `127.0.0.1:3000`. Подойдёт HTTPS-прокси на сервере или туннель для временной проверки. Он должен пропускать `/api/*`, в том числе `/api/max/webhook`.
2. Укажите этот адрес в `PUBLIC_BASE_URL` и снова выполните команду из шага 3.
3. Зарегистрируйте webhook. Команда выполняется из корня проекта, использует токен из `.env.local` и не требует Node.js на компьютере:

   ```sh
   docker compose --env-file .env.local run --rm --no-deps -v ./scripts:/app/scripts:ro app node scripts/max-webhook.mjs --apply --url=https://YOUR-HOST/api/max/webhook
   ```

   Замените `https://YOUR-HOST` своим адресом. Если подписка уже существует, скрипт покажет её и завершится без изменений. Не перенаправляйте webhook работающего бота для локального теста; используйте его действующую установку или отдельного тестового бота.
4. Для выданного на хакатоне бота отправьте HTTPS-ссылку через [форму организаторов](https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/). Они привязывают мини-приложение. Не меняйте название, username и логотип бота.
5. Откройте бота в MAX и пройдите сценарий ниже.

### Остановка и повторный запуск

```sh
docker compose --env-file .env.local down
docker compose --env-file .env.local up --build -d
```

Данные остаются в томе `planning-data`. Команда `down -v` удалит их вместе с томом.

## Проверка основного сценария

Нужен обычный аккаунт MAX; отдельного пароля V-MAX или административной роли нет. Для проверки чужого доступа и обмена планом нужен второй аккаунт. API-доступ описан в [инструкции проверки](docs/testing.md).

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Откройте бота, нажмите «Новый маршрут», введите пример из начала README. | Сохраняются город, завтрашняя дата, 14:00–18:00 и порядок «прогулка → еда». |
| 2 | Выберите старт на карте или введите адрес. Проверьте условия и запустите подбор. | Появляется план с прогулкой и едой. Если обе активности не вошли, это обозначено; ошибка источника не заменяется вымышленными местами. |
| 3 | В мини-приложении откройте карту, нажмите маркер, затем «Посмотреть на карте». | Маркер связан с карточкой; в 2ГИС передаются старт, остановки по порядку и заданный финиш. |
| 4 | Через «Добавить событие» выберите доступное событие, сеанс либо длительность, подтвердите и пересчитайте. | Событие учитывается вместе с другими занятиями; видны время и ссылка на источник. |
| 5 | Измените бюджет и радиус, очистите поле и введите новое число. | Шаг бюджета — 100 ₽, радиуса — 1 км; значение можно заменить без лишнего нуля. |
| 6 | Задайте окончание раньше начала. Затем исправьте время. | Ошибка у поля; после исправления можно продолжить. |
| 7 | Откройте «Мои маршруты», выберите план, поделитесь им со вторым аккаунтом. | Владелец открывает свой план; получатель видит условия и создаёт отдельную копию со своим стартом. |

Готовая подборка хранится до удаления; через 30 минут появляется предложение обновить её. Ввод «вечером» задаёт 17:00–20:00, «днём» — 13:00–16:00, «утром» — 09:00–12:00. Явно указанные часы имеют приоритет.

Дополнительные случаи и порядок работы с синтетическими данными — в [docs/testing.md](docs/testing.md). Синтетические сценарии не загружаются в рабочую БД и не используются вместо реальных результатов поиска.

## Данные и ограничения

PostgreSQL хранит MAX ID, условия, состояние диалога и сохранённые планы. Готовые результаты сохраняются до удаления, незавершённые условия — до 30 дней. У внешних сведений сохраняются источник и время получения. При обмене планом приватные старт и финиш не передаются; ссылка 2ГИС содержит координаты выбранного маршрута.

Сервер проверяет подпись и срок MAX `initData`, владельца плана и версии изменений. Серверные токены не передаются клиенту; исключение — предназначенный для браузера ключ MapGL. Сведения об обработке данных доступны через `/privacy` в боте и `/?page=information` в мини-приложении. Реквизиты оператора пока не заполнены.

- Для поездок на транспорте конечный общий бюджет пока не поддерживается: стоимость дороги неизвестна. Нужно выбрать бюджет без ограничений; пеший сценарий поддерживает ограничение бюджета.
- Время дороги в `external` приблизительное. Часы работы, цены и наличие билетов следует уточнить перед посещением.
- Поиск ограничен радиусом и доступными ответами каталогов. Покрытие событий зависит от KudaGo.
- Радиус по умолчанию: пешком — 5 км, велосипед — 10 км, общественный транспорт и такси — 30 км, автомобиль — 50 км.
- Полный сценарий на Android и iOS и длительные фоновые расчёты в облаке ещё требуют проверки. Локальные тесты этого не заменяют.
