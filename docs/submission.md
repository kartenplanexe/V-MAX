## Презентация

На первом техническом слайде обязательны: ссылка на бот, репозиторий и commit hash, адрес API, порядок проверки, нужные тестовые доступы и рабочие значения окружения. Если отдельных логинов и паролей у решения нет, это нужно прямо указать. Этот слайд не оценивается как продуктовая презентация. Копия с рабочими секретами предназначена только организаторам; публичная копия не заменяет её при сдаче.

Со второго слайда рекомендуются: название и команда, краткое описание, аудитория и проблема, решение и сценарий, ожидаемый эффект, архитектура, данные и интеграции, масштабирование, ограничения и источники. Структура может отличаться. Непроведённый пилот следует обозначить как план, а не результат.

## Перед отправкой

1. Зафиксируйте выбранную версию исходников; проверьте, что README и контракты соответствуют ей.
2. Соберите контейнеры по README. Требование кейса — до пяти минут без первоначального скачивания базовых образов; запишите результат измерения на машине проверки.
3. Пройдите основной сценарий в MAX и убедитесь, что API доступен по HTTPS.
4. Проверьте доступ жюри к репозиторию либо приложите ZIP с SHA-256. В архиве должны быть обязательные файлы, без `.env.local`, кэшей и локальных журналов.
5. Укажите тот же commit в презентации; приложите закрытые доступы для технической проверки. Передачу доступов нельзя заменить пустым шаблоном.
6. Отправьте комплект через личный кабинет. Согласно FAQ, срок — 30 сентября 2026 года, 12:00 МСК. Переданная версия после дедлайна фиксируется; бот должен работать весь период проверки.

## Что ещё требует подтверждения

Само наличие документов не подтверждает мобильную проверку, выполнение длительных задач в облаке, заполнение реквизитов оператора и фактическую передачу рабочих доступов жюри. Эти пункты проверяются отдельно. Полную готовность сдачи нельзя заключить только из проверки README.
