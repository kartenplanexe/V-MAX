# Настройки

Для обычного запуска выполните шаги из [README](../README.md). Этот документ нужен при изменении стандартной конфигурации. Исходный образец - [.env.example](../.env.example).

## Обязательные подключения

| Сервис | Настройки и доступ |
|---|---|
| MAX | `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`; для собственной установки в MAX - `PUBLIC_BASE_URL` с публичным HTTPS. |
| 2ГИС | `DGIS_PLACES_API_KEY` для Places, Categories и Regions; `DGIS_MAPGL_API_KEY` для MapGL и Map Tiles. Нужны действующие права и квоты. |
| PostgreSQL | Compose использует `POSTGRES_PASSWORD` и сам задаёт `DATABASE_URL`. |
| Alice Flash | `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` для разбора свободного текста. У учётной записи должна быть роль `ai.languageModels.user`. Можно пропустить, если нужна только ручная форма. |
| KudaGo | Ключ не требуется. Нужны доступ к публичному API и наличие города в каталоге. |

MAX, 2ГИС, KudaGo и Alice Flash не запускаются в Compose. Условия и описание API: [MAX](https://dev.max.ru/docs-api), [2ГИС](https://docs.2gis.com/ru), [KudaGo](https://docs.kudago.com/api/), [Yandex AI Studio](https://yandex.cloud/ru/docs/ai-studio/).

## Необязательные параметры

| Переменная | По умолчанию | Когда менять |
|---|---|---|
| `HOST`, `PORT` | `0.0.0.0`, `3000` | Запуск вне Compose. В Compose порт приложения переопределён на `8080`. |
| `MAX_INIT_DATA_TTL_SECONDS` | `3600` | Срок допустимости подписанных данных запуска MAX в секундах. |
| `DGIS_BACKUP_API_KEY`, `DGIS_TERTIARY_API_KEY` | Пусто | Резервные ключи при отказе доступа или исчерпании квоты основного. |
| `DGIS_MAPGL_ALLOW_SHARED_DEMO_KEY` | `false` | `true` разрешает общий демо-ключ поиска и карты; этот ключ становится публичным. |
| `PLANNING_ROUTING_MODE` | `external` | `verified` включает внутреннюю проверку дорог через Routing. |
| `MAX_WEBHOOK_ASYNC` | Пусто | Только `yandex` для настроенной фоновой обработки Yandex Serverless. В локальном Compose оставить пустым. |

## База вне Compose

Задайте `DATABASE_URL` и один из вариантов доверенного сертификата: `DATABASE_CA_PATH` (путь к CA) или `DATABASE_CA_PEM` (PEM). Нужны прямое подключение либо session pooling; transaction pooling не подходит для используемых блокировок.

Для собственной локальной БД без TLS разрешение задаётся явно: `DATABASE_ALLOW_LOCAL_PLAINTEXT=true`. Облачное подключение должно проверять сертификат сервера. Параметры `sslmode` в URL могут перекрывать настройки TLS клиента, поэтому их не добавляйте.

Создание отдельной PostgreSQL на ВМ описано [здесь](../deploy/postgres/README.md). Этот шаг не требуется для Compose.

## Режим verified

Для стандартной сдачи с переходом в 2ГИС он не требуется. При включении задайте `DGIS_ROUTING_API_KEY`, доступ к Routing и лимиты подписки:

| Переменная | Значение |
|---|---|
| `DGIS_ROUTING_LIMIT_MINUTE` | Максимум за минуту; в шаблоне `5`. |
| `DGIS_ROUTING_LIMIT_DAY` | Максимум за сутки; в шаблоне `50`. |
| `DGIS_ROUTING_LIMIT_MONTH` | Максимум за месяц; в шаблоне `1000`. |
| `DGIS_ROUTING_INITIAL_DAY` | Начало текущих суток: `YYYY-MM-DD`, Москва. |
| `DGIS_ROUTING_INITIAL_DAY_USED` | Уже использованная дневная квота. |
| `DGIS_ROUTING_INITIAL_MONTH` | Начало периода: `YYYY-MM-20`, Москва. |
| `DGIS_ROUTING_INITIAL_MONTH_USED` | Уже использованная месячная квота. |

Начальные счётчики берутся из кабинета поставщика. Несколько ключей одной подписки не умножают её лимиты. Без начальных данных Routing закрыт; значения по умолчанию не означают наличие оплаченного доступа.

## Существующее развёртывание Yandex Cloud

Скрипт ниже рассчитан на инфраструктуру команды: ID контейнера, реестра, сети, сервисного аккаунта и Lockbox закреплены в нём. Это не установщик ресурсов для нового облачного аккаунта.

```sh
node scripts/deploy-yandex-live.mjs --apply --external-places-demo
```

Нужны Node.js, Docker, авторизованный `yc` и права на эти ресурсы. Скрипт проверяет подключение к БД, собирает образ, обновляет ревизию и проверяет HTTP. Секреты берутся из Lockbox. После выкладки пройдите сценарий в MAX.

Для `MAX_WEBHOOK_ASYNC=yandex` требуется настроенный сервисный аккаунт асинхронного вызова ревизии. Проверка длительной задачи в этой конфигурации ещё не завершена. При самостоятельном развёртывании сначала используйте синхронную обработку на постоянно работающем сервере.
