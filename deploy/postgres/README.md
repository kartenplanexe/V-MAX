# PostgreSQL на отдельной ВМ

Для локальной проверки используйте Compose из [корневого README](../../README.md). Этот каталог нужен только для отдельной PostgreSQL 17 на Ubuntu 22.04/24.04 в Yandex Cloud.

## Установка

Подготовьте выделенную ВМ с 2 ГБ RAM и диском от 10 ГБ. Скопируйте на неё этот каталог и выполните:

```sh
sudo bash setup.sh
```

Скрипт проверяет свободное место и приватный IP, устанавливает Docker и запускает `maxbot-postgres`. При существующем контейнере или `/opt/maxbot-postgres` установка останавливается; повторная установка не является способом восстановления работающей БД.

Данные размещаются в `/opt/maxbot-postgres/data`, образ фиксируется по digest. Роль приложения `maxbot` не имеет superuser/createdb/createrole; миграции выполняются в собственной БД. Контейнеру выделен 1 ГБ RAM, журналы ограничены ротацией.

## Сеть и подключение

- PostgreSQL слушает приватный адрес на 5432 с TLS. HBA разрешает роль приложения из `198.19.0.0/16` и внутренний loopback для проверки.
- В security group разрешите TCP/5432 только из сети Serverless, SSH — только с доверенного адреса администратора. Не публикуйте базу в интернете.
- Подключите Serverless Container к соответствующей VPC. `DATABASE_URL` и CA передайте через Lockbox; скрипт `scripts/configure-yandex-secrets.mjs` находится в корне репозитория.
- `DATABASE_CA_PATH` и `DATABASE_CA_PEM` — альтернативы. Не используйте `rejectUnauthorized: false` или параметры `sslmode`, перекрывающие TLS-конфигурацию клиента.
- Лимит PostgreSQL — 40 подключений, пул одного приложения — 6. Ограничьте масштабирование контейнера с учётом остальных подключений.

## Секреты и сопровождение

Пароль генерируется на ВМ; строка подключения хранится в `private/connection.env` и не выводится. `certs/ca.crt` — публичный сертификат доверия. `private/ca.key`, `certs/server.key` и файлы паролей нельзя публиковать.

Сертификат сервера действует 365 дней, CA — 730. При смене приватного IP серверный сертификат нужно перевыпустить. Продление и уведомления не автоматизированы. Закрытый ключ CA необходимо хранить в защищённой резервной копии вне ВМ.

Резервные копии вне ВМ с проверкой восстановления и мониторинг свободного места настраиваются отдельно: `setup.sh` их не создаёт. Локальный dump на том же диске не защищает от потери ВМ.

## Проверка

```sh
node deploy/postgres/verify-local.mjs
```

Команда выполняется из корня репозитория; нужны Docker и OpenSSL (на Windows — Git for Windows либо `OPENSSL_BIN`). Она запускает изолированный временный контейнер без внешних портов, проверяет TLS и права роли, затем удаляет свои тестовые ресурсы. Подключение из облака, миграции и восстановление резервной копии проверяются отдельно.
